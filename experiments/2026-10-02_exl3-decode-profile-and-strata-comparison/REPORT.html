Ranked next probes

Strata was reviewed at immutable revision 1678de333d0e0711bc414ad992b640e1a37dd814. It was not built or benchmarked: weight formats, CPU execution and speculation differ. The useful comparison is architectural. Proposed gates below are future acceptance criteria, not achieved results. Full recommendation record.

  1. Reduce transferred bytes with byte-aware cache allocation/admission

    K3 accounts for 111.60 MiB/token versus K2’s 72.11 MiB. Replay code, prose and long-context routing traces at the existing bank budget; optimize saved bytes per cache byte. Existing precision pools already compact K2 and share capacity across layers. More K3 traffic alone does not justify more K3 capacity. Effective transfer rate was 25.50 GB/s; current link width was not measured, so saturation is unproven.

    Gate: at least 20% fewer replayed transfer bytes, then 10% higher matched geometric-mean serving speed, no workload over 3% slower, unchanged KV/concurrency budgets and checkpoint parity. Preserve global-pool semantics: historical LFU96 fell from 62.42 to 49.38 tok/s. Prior cache results.

  2. Requalify MTP, then consider cost-aware draft/lookup selection

    Compare MTP-off against MTP3 with one active request; record accepted tokens, verification cost and copied bytes per accepted token. Older MTP measurements used different settings. Strata’s draft policy combines observed cost and acceptance, with bounded exploration.

    Gate: 10% higher accepted output tok/s, no workload over 3% slower, target verification and checkpoint parity preserved. Qualify concurrency separately: the current 64-lane planner cannot cover four requests × four verification rows × top-k 10 = 160 lanes. Enabling MTP3 in today’s four-sequence launcher requires capacity work.

  3. Overlap resident expert work with miss staging

    Prototype one real layer with hit/miss partitions, stable staging slots and completion events. Strata publishes resident GPU work first and commits asynchronous residency changes after completion. Our serialized path needs explicit mapping/slot ownership changes; its copy kernel consumes SMs and cooperative compute may constrain overlap.

    Gate: changing-route graph correctness and 15% lower layer latency before a full-model trial. Halving copy time gives a conditional 1.236× instrumented model-step bound; it is not an expected serving gain.

  4. Attribute backbone time before another expert-math rewrite

    Add a few backbone boundaries to resolve the 41.60% remainder. Gate: identify a component consuming at least 10% of model-step time before implementing, then require parity and 10% matched serving gain. Halving routed expert compute has only a conditional 1.078× model-step bound. The previous HC prototype failed real-checkpoint parity, and cooperative-fast preparation failed its latency gate. Prior kernel results.

  5. Pipeline prefill staging and reuse residents

    Current eager prefill stages every expert in each layer. Profile one 8K or 32K prompt before trying Strata’s resident-skipping, event-fenced staging ring. Gate: 15% lower cold-prefix TTFT at fixed memory, packed-byte and numerical parity, and safe slot reuse. Extra staging competes with KV/cache capacity; retain TEMP_ROWS_FUSED=2048. Prefill was not measured here.

  6. Defer CPU/GPU hybrid execution until one EXL3 expert wins

    Strata runs CPU misses alongside GPU work, using other weight layouts. This AVX-512-capable host has no qualified CPU EXL3 backend. Gate: one K2/K3 expert must pass parity and beat avoided transfer-plus-GPU latency, including activation/result handoff and synchronization, before integration. This is an architecture experiment; model conversion is outside scope.
