Decode optimization controls

The additional cooperative decode optimization is experimental and disabled by default. The existing expert cache and fused planner remain available as before.

Explicit opt-in

# Set before starting the server. Existing launch scripts preserve these variables.
export VLLM_EXL3_COOP=1
export VLLM_EXL3_COOP_DECODE_FAST=1

# To restore general route preparation, restart with:
export VLLM_EXL3_COOP_DECODE_FAST=0

The switch accepts exactly 0 or 1; other values raise an error. It is read at import, so changing it requires restarting the server and recapturing graphs. vllm_exl3.runtime_diagnostics() reports the selected value under optimizations.coop_decode_fast. The optimization only applies when the cooperative kernel is enabled and eligible, and the token count cannot exceed the large-expert threshold. Other calls use the existing general preparation.

The change omits unused token indices, expert histograms and large-expert masks before small cooperative calls. It preserves routing validation, sentinel handling, kernel arithmetic, output initialization and completion counters.
